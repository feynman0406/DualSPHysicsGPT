# MVP: Direct OpenAI File Search Two-Stage Workflow

## Overview

This MVP demonstrates the simplest possible two-agent workflow for DualSPHysics configuration generation:

1. **Agent 1** (Reference Finder): Uses OpenAI file_search to find relevant example configurations
2. **Agent 2** (Config Generator): Uses those references to generate a strict JSON config
3. **XML Generation**: Converts config to XML
4. **Execution** (optional): Runs GenCase


## What Happens

### Agent 1: Reference Finder
- **Input**: User query
- **Process**: 
  - Creates OpenAI thread with file_search enabled
  - Searches vector store for relevant examples
  - Extracts citations and file references
  - Provides analysis of what was found
- **Output**: `logs/mvp/agent1_output.json`
  - `query`: Original query
  - `references`: List of relevant files found
  - `analysis`: LLM's analysis of the references
  - `instructions_for_agent2`: How Agent 2 should use them
  - Note: `references` now contains only lightweight file metadata. Agent 2 resolves the actual JSON locally from `AutoXml_script/config_library/`.

### Agent 2: Config Generator
- **Input**: Agent 1's output + JSON schema
- **Process**:
  - Loads `schemas/dualsphysics_config_schema.json`
  - Builds prompt with references and instructions
  - Calls OpenAI with strict JSON schema enforcement
  - Generates config matching schema exactly
- **Output**: `logs/mvp/agent2_config.json`
  - Complete DualSPHysics configuration JSON

### XML Generation
- **Input**: Agent 2's config
- **Process**:
  - Normalizes config (handles defaults, validation)
  - Generates XML using `generate_case_xml()`
  - Saves to file
- **Output**: `logs/mvp/generated_case.xml`

### Execution (Optional)
- **Input**: Generated XML
- **Process**: Runs GenCase executable
- **Output**: `logs/mvp/case_out/` (simulation files)

## Advantages of This Approach

1. **Simplicity**: Direct use of OpenAI APIs, minimal abstraction
2. **Visibility**: Clear separation of Agent 1 and Agent 2 outputs
3. **Inspectable**: Can pause and review intermediate results
4. **Debuggable**: All outputs saved to files for analysis
5. **Transparent**: Shows exactly what each agent receives and produces

## Comparison with Production System

This MVP is **simpler** than the production system in `chains/generator.py`:

### MVP (This Script)
- Direct OpenAI API calls
- Simple two-stage workflow
- Manual output inspection
- No retry mechanism
- No metrics tracking
- No complex error handling

### Production System
- Uses `planning_agent.py` and `schema_agent.py` classes
- Integrated with `generator_chain()`
- Automatic fallback to single-stage
- Example scoring (4 dimensions)
- Quote extraction (<400 chars)
- Parameter extraction
- Coverage detection
- Gap/conflict detection
- Plan JSON validation
- Metrics tracking (partial)

## Troubleshooting

### "Missing required environment variables"
- Ensure `OPENAI_API_KEY` and `OPENAI_RAG_VS_DESIGN_ID` are set
- Check values with: `echo $OPENAI_API_KEY`

### "Vector store not found"
- Verify vector store ID is correct
- Check it exists: Use OpenAI dashboard or API

### "Schema validation failed"
- Agent 2's strict schema enforcement failed
- Review `logs/mvp/agent1_output.json` to see if references were good
- Try a simpler query first

### "XML generation failed"
- Config JSON doesn't match expected structure
- Check `logs/mvp/agent2_config.json` for issues
- Review normalization warnings
