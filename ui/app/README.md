# DualSPHysics Control Center UI

This package contains the front-end application for the DualSPHysics MVP orchestration UI. It is built with React, Vite, and TypeScript. The UI surfaces run management, execution details, log streaming, and artifact browsing for the MVP wrapper introduced in Phase 1.

## Getting Started

```powershell
cd ui/app
npm install
npm run dev
```

The dev server proxies API requests under `/api` to `http://localhost:8000` by default. Update the proxy target in `vite.config.ts` if the backend runs on a different port.

## Common Scripts

| Command                | Description                                                       |
| ---------------------- | ----------------------------------------------------------------- |
| `npm run dev`          | Start the Vite development server with hot module replacement.    |
| `npm run build`        | Type-check the project and produce a production build in `dist/`. |
| `npm run preview`      | Serve the production build locally for smoke testing.             |
| `npm run lint`         | Run ESLint on all TypeScript/TSX files under `src/`.              |
| `npm run lint:fix`     | Attempt to automatically fix linting issues.                      |
| `npm run format`       | Check formatting against the Prettier configuration.              |
| `npm run format:write` | Apply Prettier formatting to supported file types.                |
| `npm run test`         | Execute Vitest once in headless mode (JS DOM environment).        |
| `npm run test:watch`   | Execute Vitest in watch mode during development.                  |

The integration smoke test lives in `ui/tests/smoke.spec.ts` (repository requirement). Vitest runs it through a thin proxy in `ui/app/tests/smoke.spec.ts`, so no extra configuration is required.

## Mocking the Backend

The MVP wrapper APIs are still evolving. During development you can provide mocked responses by overriding methods in `src/services/api.ts` (see inline documentation) or by using devtools such as `msw` for network-level interception.

## Coding Standards

- The project uses ESLint with TypeScript and React rules via `@typescript-eslint` and `eslint-plugin-react`.
- Prettier enforces formatting with a 100-character print width.
- React Query powers remote state management for consistent loading/error handling.
- UI states should align with the behaviour outlined in `docs/ui_integration/ui_state_matrix.md`.
